# AI 漫剧生产流水线

人物资产和分镜首帧支持两条生图后端：`GPT Image 2 + cinematic-image2-spec`，或本地 `Z-Image-Turbo + ComfyUI`。两条路线的图片都必须经过人工确认，再进入统一的故事板和 MiniMax H3 视频流程。

## 本地 Z-Image-Turbo 后端

本地环境：`<COMFYUI_ROOT>`，启动对应的 GPU 启动脚本，界面通常为 `http://127.0.0.1:8188`。

- 主模型：`ComfyUI\models\diffusion_models\z-image-turbo-fp8-e4m3fn.safetensors`
- VAE：`ComfyUI\models\vae\ae.safetensors`
- 文本编码器：`ComfyUI\models\text_encoders\Qwen\qwen_3_4b.safetensors`
- 参数：`CLIPLoader=lumina2`、8 步、CFG 1、`res_multistep/simple`、`ModelSamplingAuraFlow shift=3`；负向条件走 `ConditioningZeroOut`
- 文生图：`Z-Image-Turbo-8步出图-修复版.json`
- 图生图：`Z-Image-Turbo-图生图.json`，`LoadImage → VAEEncode → KSampler`，首轮 `denoise=0.7`
- 批量候选：使用 Queue 的 batch count 和随机 seed；输出在 `ComfyUI\output\`

不要使用 Mie 内置的 `z-image_turbo.json`：它是需要 `svdq-fp4` 的 nunchaku 版本，与当前 FP8 模型不匹配。Z-Image 只负责图片，不负责视频和声音；精选图片作为 H3 的 `first_frame`。

## 目标

把一个故事拆成用户能审核、模型能执行、视频能验收的中间产物。核心原则是先锁叙事，再锁人物与场景，再锁分镜首帧和故事板，最后逐镜头拍摄；不要把第一张生成图直接当成正式视频输入。

## 前期生产分层补充

将前期工作固定拆成五层，减少把小说、剧本、角色设定和视频提示词混在一次对话里的情况：

```text
角色资产 → 场景/道具资产 → 场次节拍剧本
→ 2～5 秒单动作子分镜 → 首帧/提示词投产包
```

- 角色资产先锁定脸、发型、体型、服装、色彩和关键道具。
- 场景资产先锁定空间结构、固定陈设、主光源、色温和可用机位。
- 剧本阶段明确场次、节拍、动作/对白和镜头时长，不直接让视频模型理解整段剧情。
- 子分镜阶段将复杂事件拆成多个 2～5 秒片段，每条只保留一个主要物理动作。
- 投产包阶段再写生成分支、首帧、动作时间线、声音、禁止项和验收项。

这部分是对现有流水线的补充，不新增独立 Skill，也不替换已有的 GPT Image 2、Z-Image-Turbo、豆包、MiniMax H3 和 SeedVR2 分工。

## 适用项目规则

如果当前目录存在项目 `AGENTS.md`，先读取并遵守其中的人物、时代、服装、道具和版权设定。项目设定优先于本 Skill 的通用默认值。

## 标准流水线

```text
剧本
→ 多组人物资产候选
→ 用户选择人物资产
→ 多组分镜首帧候选
→ 用户选择正式首帧
→ 故事板锁定
→ MiniMax H3 图生视频（画面 + 原生声音）
→ SeedVR2 高清修复
→ 按故事板拼接
→ 人物、动作、声音和画质质检
```

## 闸门规则

### 闸门一：剧本

输出故事梗概、角色关系、镜头数量、每镜头的单一主要动作和声音需求。单集首轮建议 30~60 秒、8~15 个镜头；本地低显存测试先做 3~5 秒单镜头。

### 闸门二：人物资产

为主要角色生成母版、三视图、表情和动作参考的候选组。每个候选必须记录角色编号、版本、服装、发型、道具和用途。等待用户选择后，才把角色标记为正式资产。

### 闸门三：分镜首帧

生成分镜首帧前调用 `cinematic-image2-spec`，将每个动作转换为可执行的摄影规格。每个镜头先生成约 4 张构图候选，只允许变化景别、站位、前景遮挡和光线强弱，不改变人物身份、时代、服装、场景和主动作。

每个镜头的首帧说明必须包括：

- 导演意图：观众感受到什么，摄影机为什么这样安排。
- 画幅、景别、机位、构图和焦段倾向。
- 主光来源、明暗关系、曝光和色彩分离。
- 场景空气、材质和道具连续性。
- Image 2 提示词、可选约束和 2~3 个重试旋钮。

`cinematic-image2-spec` 负责静帧摄影规格；需要视频动作和逐秒时序时，衔接 `cinematic-story-director` 或 `ai-manjue-video-shot`。

### 闸门四：故事板

用户选定人物和首帧后，建立故事板。每行至少包含：镜头编号、故事位置、首帧文件、角色、人物站位、唯一主动作、0~2 秒动作、2~4 秒动作、镜头运动、环境变化、对白、环境声、禁止事项、接前状态、接后状态和 H3 状态。

每行同时作为一张“镜头投产卡”，建议固定记录：`shot_id`、镜头目的、角色/场景锚点、首帧文件、景别与机位、动作时间线、对白或静默、生成分支、禁止项、验收结果。这样同一镜头切换豆包和 H3 时，只替换执行端，不重写剧情。

故事板是后续拍摄的唯一依据；不要让 H3 直接读取零散剧本或临时聊天提示词。

### 闸门五：H3 拍摄

默认使用：

`<MINIMAX_H3_ROOT>\workflows\video_minimax_h3_i2v_seedvr2_hd_8gb_v2.json`

执行规则：

- 每个镜头单独运行，首帧连接 `first_frame`。
- 只有需要明确结束姿态时才使用 `last_frame`。
- 每段控制在 3~5 秒、一个主要动作，复杂动作拆镜头。
- H3 优先原生生成画面、对白和环境声，使用 `audio_vae` 保留音频；不默认调用 TTS。
- 固定角色声音描述，并在同角色镜头中重复使用。
- 8GB 显存使用 CPU offload / 显存交换和保守参数；不要照搬 12GB 配置。

### 闸门六：SeedVR2 和质检

SeedVR2 是重建式高清，不是简单锐化。先检查 H3 原片，再检查高清版本。当前 8GB 默认采用 `resolution=512`、`max_resolution=720`、`batch_size=1`，速度较慢但优先稳定。

重点检查：

- 人脸、发型、服装、道具是否连续。
- 手部、脚部、衣物和背景是否出现重建伪影。
- 主动作是否真实完成，而不是只有摆头、眨眼或衣摆飘动。
- H3 原生对白、口型、环境声是否合理。
- 画面比例、亮度、色彩和镜头衔接是否符合故事板。

如果高清版比 H3 原片更不自然，保留 H3 原片，优先返工首帧、降低动作复杂度或缩短镜头，不盲目提高放大倍率。

## 每次交付格式

按阶段只报告：

1. 状态：当前通过了哪一道闸门。
2. 已完成文件：角色资产、首帧、故事板、视频或质检记录。
3. 待用户确认：需要用户选择的候选和具体问题。
4. 下一步输入：通过后才进入的下一阶段。

没有通过闸门时，不宣称整条成片完成。
